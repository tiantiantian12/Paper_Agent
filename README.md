# Paper Agent

面向毕业论文写作的智能体桌面应用。基于 **PySide6 6.9** + **Python 3.13**，
类 Codex 风格：白/暗双主题、左栏对话记录、底部输入区、右侧论文结构面板，
支持粘贴/拖入图片与文档附件、Markdown 渲染、代码块高亮与一键复制。

> 当前为 UI 联调版本，回复由 `paper_agent.services.mock_engine` 中的示例
> 模板生成；接入真实大模型时只需保持 `AgentService` 的信号协议不变。

---

## 环境

- Python 3.10+ （已在 3.13 测试）
- PySide6 6.6+ （已用 6.9.1 测试）
- ffmpeg（**视频功能需要**，见下）：`requirements.txt` 里的 `imageio-ffmpeg` 自带一份
  二进制，`pip install -r requirements.txt` 就够了；系统里已装 ffmpeg 的话也会优先用它
  （找不到时：首尾帧续接与长视频合成都不可用，分段出片仍然正常，并会明确提示怎么装）
- ⚠️ **要装在「运行本程序的那个 Python 环境」里**：如果你像本机一样有多个环境
  （比如测试用 3.12、程序跑 conda 的 `pyqt6`），只给其中一个装是不够的 ——
  程序在另一个环境里找不到 ffmpeg，「取末帧」就会全部失败。验证一句话：
  `python -c "import imageio_ffmpeg; print(imageio_ffmpeg.get_ffmpeg_exe())"`
  （用**启动程序的**那个解释器跑）
- 推荐 conda 环境 `D:\apps\anaconda3\envs\pyqt6`（Python 3.13）

```powershell
conda activate pyqt6
pip install -r requirements.txt
python main.py
```

## 主要功能

- **界面风格**：白 / 暗主题切换，1px 细边框 + 圆角，类 Codex 极简布局
- **无边框窗口**：自定义标题栏（拖动 / 双击最大化 / 缩放 / Win11 圆角）
- **左栏会话列表**：新建、搜索、按时间分组、重命名、删除、导出为 Markdown；
  编程会话会带一个「编程」徽标，不点开也能分清哪个会话在写代码
- **底部输入区**：
    - Enter 发送 / Ctrl+Enter 换行（可切换）
    - 工具条：附件、图片、工作模式、深度写作、推理强度
    - 粘贴 / 拖入图片（自动保存并附在消息中）
    - 粘贴 / 拖入文档（PDF / Word / Markdown / TXT / 代码等）
- **工作模式**（输入区左侧下拉，**按会话记忆**）：
    - **文档模式**（默认）：论文写作 + Word / PPT / PDF / Excel 排版出稿，
      挂载 create_docx / create_pptx 等文档工具，工作区文件清单与会话产物管理都生效
    - **编程模式**：配置环境、写代码、跑代码。换成工程工具集
      （write_file / read_file / list_files / run_command / execute_python），
      并切换到工程助手的系统提示词
        - 所有读写与命令都在**工作区目录**内进行：**每个会话一份**，
          默认 `<数据目录>/workspace/<会话 id>`，会话之间互不共享；
          可用右侧面板的文件夹按钮给该会话单独指定目录（记在会话上，
          也可用环境变量 `PAPERAGENT_CODE_ROOT` 全局覆盖）
        - **只有「真写过工程文件」的会话才会被钉在共享目录上**（兼容改版前的老数据）：
          判据是历史里用过 `write_file` / `run_command`。早先的判据是「共享目录非空」
          + 「有任何工具调用」，于是**所有**切过编程模式的会话都会被钉过去 ——
          上传的附件跟着落到 `workspace/` 根目录（别人工程旁边）、而不是本会话自己的
          目录。另外判断「共享目录里有没有老文件」时也排除了 `workspace/<会话 id>/`
          这些会话自己的子目录（否则它们自己就足以让父目录"非空"）
        - **右侧面板变成「代码工作区」**：显示工作区目录树（目录/文件图标、文件大小，
          双击用系统默认程序打开），右上角文件夹按钮可**选择任意文件夹作为工作区**，
          选择会记住；刷新按钮手动重扫（生成结束也会自动重扫）
        - **右键菜单**：文件可打开、复制文件、复制地址、在文件管理器中显示、重命名、删除；
          目录可复制地址、在管理器中打开、重命名、删除（连同内容）；空白处可新建文件 /
          文件夹、打开工作区、刷新。所有改动都被限制在当前工作区内
        - **上传的附件会先复制进工程目录**（`code_workspace.import_attachments`）：
          附件平时存在 `data/attachments`，而编程模式的工具都钉在工程目录内 ——
          不复制的话模型在工程目录里看不到用户传的文件，只会回「找不到这个文件」。
          复制是**幂等**的（同名同大小跳过，连续对话不堆副本），工程目录里已有同名文件时
          另存 `-1` 而**不覆盖**。顺序上先复制、再扫文件清单，所以这一轮注入的
          「工程目录现有文件」里就带着它们，模型立刻知道有这么个文件
        - 目录之外的写入会被拒绝；删除限工程目录与白名单；破坏性系统指令（format / diskpart 等）直接拒绝
        - 编程模式下 execute_python 放开子进程限制（可以装依赖、跑构建），
          运行目录也钉在工程目录里
    - 模式记在**每个会话**上：论文会话写论文、工程会话写代码，切换会话时界面
      （输入区提示语、助手称谓、右侧面板、空会话的欢迎页引导）跟着一起切；
      **新建会话默认文档模式**
- **模型下拉**：自定义菜单（名称 + 描述 + 选中标记），模型选项与推理强度解耦
    - **内置模型（服务端代理）**：`SenseNova 6.8 Flash Lite` 等内置模型不直连供应商，
      请求统一走服务端中转；供应商的 Base URL 与 API Key 都由服务端看板管理，
      桌面端只用服务端签发的**用户代理密钥**（登录后自动取回并缓存）
    - **内置模型清单由服务端维护**：看板里改名字 / 备注、**新增模型**（配好密钥即可），
      桌面端下次启动或重新登录就跟着变，不用发新版 —— 新增的模型自动走同一条服务端
      代理链路，本地不需要任何配置
    - 下发的清单缓存在 `settings.ini` 的 `llm/builtinModels`，退出登录时清掉并回退到
      本地默认清单；拉不到（未登录 / 服务端没起）沿用本地清单，不报错。服务端删掉
      某个模型时，下拉框里随之消失，选中项自动回退到可用的内置模型
    - 密钥未配 / 已过期 / 被停用时，桌面端给出可操作提示（不会静默失败）；
      未登录时保持离线示例引擎
    - 本地清单里只留通用的示例模型（`GPT-5` / `GPT-5 mini` / `Claude Sonnet 4.5` /
      `DeepSeek-V3`），真正能用的都从服务端下发
- **文生图也是服务端代理**：看板里把模型类型选成「文生图」（如 `sensenova-u1.5-lite`）
  并配好密钥池后，桌面端出图走服务端 `/api/llm/v1/images/generations`，
  **供应商那把 Key 不再下发到客户端**
    - 出图同样吃密钥池轮换与限流冷却（图比对话更容易撞 429）
    - 未登录 / 服务端没配生图模型时，回落到本地 `settings.ini` 的 `image/*` 配置
      （默认是内置的那把 SenseNova Key），离线也能出图
    - 服务端新增一个生图模型（类型选文生图）后，桌面端下拉框里会多出这一条，
      选中它就直接按它出图
    - 请求体**按供应商分开拼**（字段写错会被直接 400 打回）：标准口味是
      `model` / `prompt` / `n` / `size` / `output_format` / `response_format` /
      `watermark`（**`watermark` 默认关**：公测期间去水印免费，带水印的图不适合直接交付，
      PPT 背景图同样关；`response_format` 用 `b64_json`）；Agnes 口味只发
      `model` / `prompt` / `size` + `extra_body`
    - **图生图**：`generate_image` 工具多了 `reference_image`（图片 URL / 本地路径 /
      本会话已有图片的文件名，本地图会内联成 data URI；**可以一次给多张**，逗号分开）。
      说「把这张图改成 XX 风格」「保持构图重画」时模型会用上它，参考图走 Agnes 的
      `extra_body.image`
    - **「定妆图 / 人物形象」必须走图生图**：只给文字描述的话，模型是按描述**另画一张脸**
      （实测：全是文字时出来的人和照片里的人不是同一个）。这条**规则本身**写在
      `services/skills/image_prompt.py`（和视频那条一个套路：放进**模型看得到的地方** ——
      `generate_image` 的工具说明 + `prompt` / `reference_image` 参数说明），模型自己就会照做；
      另有兜底 —— **本轮上传了图片**（attachments）**且提示词在说人物 / 定妆 / 形象 / 五官**时，
      客户端自动把那张照片挂上当参考图（最多 2 张），结果里会注明「已自动带上你上传的
      照片作为形象参考」。提示词说的是流程图 / 风景这类时**不挂**，免得把无关照片掺进画面。
      上传的原图会先压到 1280 宽再内联（实测 2.4MB 手机原图 → 0.2MB）
    - **图片规范里还钉了三条**（都来自真实事故，不是假想）：① 人物类**必须**填
      `reference_image`（不给就是换脸）；② 一次能给**多张**（「角色A.png,角色B.png」）；
      ③ 图生图仍是**重画** —— 风格词越重越容易盖掉五官，提示词里要写明
      「**严格保留五官与脸型、不要改变面部特征**」，强风格词（电影级 3D 渲染 / 灰尘 /
      疲惫感）放轻或去掉；④ 要「**视频里像本人**」时别先做一张定妆图当中间产物 ——
      直接拿**原照片**当 `generate_video` 的 `anchor`（每多一次生成就少一分像）
    - **Agnes 每次只出 1 张**（`n` 只能为 1，传 2 会被 400）：要 2 张就拆成两次请求，
      客户端自己拆；命中「503 生图队列已满，请稍后重试」会退避重试（400 这类参数错误
      不重试，立刻报错）
      以便直接落盘，若服务商只回图片地址也会自动下回来
- **文生视频也是服务端代理**：看板里加一条「类型 = 文生视频」的模型即可
    - **下拉框选中它时**，输入区会自动多出「时长 / 画幅」两个参数组件（分辨率固定 720P），
      发一句画面描述就出片；带上图片附件就是**图生视频**（图片内联成 `data:` 链接作参考图）
    - 出片是「提交任务 → 每 5 秒轮询 → 下载落盘」，按 Esc 可随时放弃；产物直接内联在对话里，
      **点播放就地播**（解码器不支持时自动改用系统播放器，提示里带上失败原因）；
      Qt 的 FFmpeg 后端默认会把容器信息（`Input #0` / `Stream #0:0` / `MFT name` …）
      按 info 级别刷到 stderr，看着像报错 —— 首次播放前会把它静音（见
      `utils/ffmpeg_log.py`），真正的播放失败走 `QMediaPlayer.errorOccurred`
    - **画面走 `QGraphicsVideoItem`，不用 `QVideoWidget`**：后者是原生窗口，由系统直接
      往屏幕上画、Qt 管不到它 —— 嵌在滚动区里会盖住兄弟控件并在下方留残影（表现为
      「点播放后下面的内容像叠在一起」）。图形视图由 Qt 自己画进后备缓冲，参与正常的
      重绘与裁剪（`card.grab()` 能抓到画面就是这条的证据）
    - **播放很吃资源，所以有三条节流规矩**（实测单个 720P 视频约占 15% 单核）：
      同一时间**只播一个**（点第二个视频自动暂停前一个）、**滚出视野就暂停**
      （看不见了没必要继续解码）、播放器惰性创建且随卡片销毁。
      滚动期间实测 CPU 从 0.36s/3.2s 降到 0.06s
    - **消息里带进度条**：刚提交（还没查到百分比）时用不确定动画，出片途中显示进度，状态栏同步
      写着「视频生成中 40%（出片要 1–3 分钟）…」，出片后转「正在下载…」；本轮结束（成功 / 失败 /
      停止）自动收起，不会留一个假进度在界面上
    - **进度会「抹平」**：供应商的 `progress` 粒度很粗（实测只在 0 → 10% → 100% 跳，
      中间一两分钟一个数都不给，用户看到的就是「卡在 10% 然后突然完成」）。客户端在两次真实
      上报之间按时间做**递减外推**（`_ProgressPacer`）：越久估得越靠前、越接近上限走得越慢，
      出片前不越过 95%，真实值只进不退；出片那一刻才跳到 100
    - 智能体自己调 `generate_video` 出片时进度同样会推上来（工具在 worker 线程里同步跑，
      进度经内部信号回主线程），不是只有「手动选视频模型」才看得到
    - 供应商对「查任务」也限流（查太密会回 429「查询过于频繁」）：轮询命中 429 / 503 时
      自动退避（最长 20 秒一次）继续等，不当成生成失败
    - **「503 视频队列已满」会自己等一会儿重投**（`SUBMIT_RETRY_DELAYS = 20s / 45s`，
      最多重试两次）：供应商的队列是**整个服务**的（实测两把 Key 同一时刻都收到
      `video_queue_full`，换 Key 没用），只能等它腾位置。而长视频一段一段串行投 ——
      前几段都出来了、最后一段被拒就整条残了，所以提交阶段也要退避重投；
      界面会显示「服务繁忙（视频队列已满），等一会儿自动重试…」，期间 Esc 能中断。
      只有 429 / 503 这种「忙」才重试，参数 / 鉴权错误立刻报错（再等也是同样的错）
    - **「没生成却说生成了」会被拦住**（`engine.VIDEO_CLAIM_RE`，同图片那条）：
      小模型（flash 级）会照着历史里 `已生成 1 段视频（文生视频）：视频-xxx.mp4` 这种
      **工具返回格式**，凭空写一段完成汇报，实际一次 `generate_video` 都没调 ——
      用户以为片子好了，去产物目录找什么都没有。凡是正文里出现「视频已生成 / 已合成一条
      长视频 / 视频-2026….mp4」而本轮**按扩展名查不到任何视频产物**时：先补一轮明确
      要求它真去调工具；还是没产物就在正文末尾挂一句醒目的「事实校验」说明。
      **注意这不是温度问题** —— 编造是「模仿历史格式」，不是采样随机性（我们发的
      温度本来就是 0.7，比官方默认 1 更低），调温度治不了，只能事后校验
    - **提示词与分镜有规范，模型自动照做**（`services/skills/video_prompt.py`）：
      三条规则写在**模型看得到的地方**（`generate_video` 的工具说明 + `prompt` / `shots`
      参数说明），所以不用用户叮嘱它就会照这个写 ——
      ① **五段式**：主体（带可辨识特征）→ 动作序列（按时间先后）→ 环境与光影 →
      镜头语言（景别 + 运镜）→ 风格关键词；② **时间戳时间线**：按**整片时间轴**写清每个
      时间段演什么（`0-4秒：… 4-8秒：… 8-12秒：…`，从 0 开始、连续铺满总时长）——
      客户端按实际分段切开（见下一条）；③ **显式衔接点**：每段收在一个明确的画面上，
      下一段从它接。第三条客户端还会**真的去用**：装配每段提示词时把「下一段的分镜」
      点名写给视频模型
      （`End this shot on a clear, steady frame that the NEXT shot can continue from: …`），
      最后一段换成收尾提示。这三条借鉴自开源社区给「即梦 Seedance 2.0」写的提示词 skill，
      但**只吸收与平台无关的部分**：它的 `@图片1` 引用语法、「全能参考」、`将@视频1延长`、
      原生音效、2K 都是即梦专有，我们的供应商不认，一条都没抄；另外它明确**不支持上传
      写实真人脸素材**，而我们的「像本人」链路正是拿真人照片当 anchor —— 哪天换到那个
      平台，这条路直接不可用
    - **时间线切片：模型按时间点划分画面，视频模型照它演**（`services/skills/video_timeline.py`）。
      用户的原话：「我要模型按时间线划分好每个时间点的画面内容后，视频模型按划分好的来」——
      实测视频模型**会**遵守 `0-4秒 / 4-8秒 / 8-12秒` 这种时间戳（包括按时间点切换景别 / 机位），
      所以关键不是「能不能切」，而是**时间线有没有写全、有没有送到对应那一段**。客户端这么做：
        1. 模型写**整片时间轴**（写进 `prompt`，或每条带秒数范围放进 `shots`）；
        2. 客户端按**实际分段**（每段 4–12 秒）把它切开：逐段取与该段时间范围相交的条目、
           **把时间戳重算成「这一段自己的 0 起点」**，于是每段都明确写着「这几秒演什么」；
        3. 时间线没铺满总时长 → 没被覆盖到的那一段补一句
           `This shot lasts the FULL N seconds…`（否则视频模型会原地重演，用户看到重复画面）。
      顺带修掉两个真 bug：
        - **时长档位外的秒数会掉成 5 秒**（2026-09-24 的真实事故）：供应商只认
          `4/5/6/8/10/12` 秒，而装配层在 `≤12` 时直接用请求值（`[11]`），客户端发现
          「11 不合法」就**静默回落默认值 5** —— 用户要 11 秒拿到 5.18 秒的片子，文案
          还写着「约 11 秒」，连问三次「为什么一直给我 5 秒的」。现在两处都改成
          **就近上调**（7→8、9→10、11→12；`video_client.snap_seconds`），并在结果里
          如实说「11 秒不在档位里，已按 12 秒生成」；工具说明也把这几档写给模型看
        - **≤12 秒时多条分镜被静默丢掉**：老代码 `texts[:1]` 只留第 1 条，用户写的
          `4-8秒 / 8-12秒` 整段消失（会话 `5bb3daf924d8` 撞上过）。现在**并成一条**原样发出，
          并如实备注「N 条分镜已合成一条时间线」；
        - **单段没有「没铺满」兜底**：写 `0-7秒` 却要 8 秒时，以前直接 `return`，现在同样补。
      结果备注一律说实话：合并了几条、按时间线切了几段、哪几秒没写画面、时间线比时长还长
      （`video_skills.timeline_notes`）—— 不再出现「内容被砍了但看不出来」
    - **对话模型也能调用视频模型**：智能体多一个 `generate_video` 工具，检测到你要视频就自己调，
      关键参数（提示词、时长、画幅）由它按你的意图决定，不用手动选
    - **段与段之间「内容重复」怎么压**（`video_long.RECAP_LINE`）：每段是**独立生成**的，
      视频模型只看得到「这一段自己的提示词 + 参考图」，**看不到前面几段演了什么** ——
      光在提示词里说「别重复上一段」落不了地，因为它不知道上一段演了什么（用户实测反馈
      「下一段重复上一段的话和动作」，根子就在这儿）。所以后面每一段都会带上
      **前面几段演了什么**的摘要（最近 3 段、每段截 120 字符）＋「接着演下一幕、
      不要重演上面任何动作/台词/运镜」。追加锚点的优先级也据此排：
      **固定主角/场景 > 已演过摘要 > 叙事阶段 > 别换脸 > 接着演** —— 预算不够先丢
      「别换脸」（脸飘一点）也要保住摘要（丢整段就成重播了）。没给分镜时分母还有个
      兜底：每段标 **叙事阶段**（opening / middle / finale），免得同一句话生成三段一样的
    - **拍续集能接得上（首尾帧控制）**：要「接着上一段继续」时，智能体会带上
      `continue_from=上一段视频的文件名`，客户端取那段的**末帧**当新片的**首帧**
      （`mode: keyframe`，帧用 ffmpeg 现抽、编码成 JPEG data URL 随请求发走），两段画面无缝衔接；
      想精确控制起止画面也可以直接给 `first_frame` / `last_frame`
      （注意：这条走的是**智能体工具链**，即在对话模型下发「接着上一段拍」；
      手动选中视频模型直接出片时不带首帧）
    - **长视频（超过 12 秒）会自动分段续接再合成**：供应商单段最长 12 秒，所以
      「来一个 30 秒的」会拆成 [10, 10, 10] 三段**续接**拍（第 1 段末帧 = 第 2 段首帧，
      见 `services/video_long.py`），全部出完后用 ffmpeg 无损拼成一条连贯长视频
      （`mode: copy`；各段编码参数不一致时自动退回重编码，见 `services/video_merge.py`）。
      规则有两条是照着「用户等不起」定的：**段数优先于精准**（9 秒给一段 10 秒，
      而不是 [5, 4] 两段 —— 少一次生成就少等一两分钟）、单次上限 60 秒（5 段，
      再长等待与额度都顶不住）
    - **每段要有自己的提示词，否则三段会长一个样**：每段是独立生成的 10 秒片子，
      若几段收到同一句「片头：废墟城市 + 快速剪辑 + 丧尸手伸出…」，那每段都会把
      整片画面重演一遍 —— 实测用户报过「要 30 秒，三段内容大量重复」（同样的相对位置、
      三段之间的画面差只有 20–45，而同一段自己 10 秒内的变化是 73–77，即三段在演同一件事）。
      所以 `generate_video` 支持 **`shots` 分镜**：每段一条提示词、按顺序传
      （30 秒 → 3 条：开场 / 中段 / 收尾），每段只演一件事；条数不足沿用最后一条、
      多余截掉，工具会把「实际分了几段」回报给模型。
      没给分镜时客户端兜底：第 1 段原样，后面几段补一句
      「continuation shot i of n… do NOT repeat what already happened」（`video_long.CONTINUATION_HINT`）
    - **「后面几段主角换脸 / 背景对不上」怎么压**：接续只靠**一帧**做锚点（上一段末帧
      → 下一段首帧），而人物在 720P 里只占很小一块，模型是拿这一帧**重新想象**人物的
      —— 脸和背景细节本来就会飘，这是供应商那一刻画能力的边界，我们只能把**文字锚点**补足：
      ① `subject`（主角与场景的固定措辞，如「穿白 T 恤的短发年轻男子 / 废弃高铁车厢」）
      每段原样带上；② 没给 subject 时，后续段自动补一句 `Keep it visually IDENTICAL…the
      SAME people (identical faces, hair, age, body type and wardrobe)…do not change the
      setting`（`video_long.IDENTITY_HINT`）；③ 模型各段提示词要用**同样的措辞**写角色
      （别一段「年轻男子」、另一段「少年」）。
      追加的锚点有字符预算（`MAX_PROMPT_CHARS`，默认 2500；用户提示词实测 1031 字符），
      优先级：固定主角/场景 > 人物一致 > 接着演 —— 预算不够先丢最后那个
    - **`seed` 是安慰剂（实测，别再试）**：想过「整条片子共用一颗种子」来压跨段漂移 ——
      实测供应商不认这个字段：同样首帧 + 同样提示词 + **同一个 seed** 跑两次，画面差
      15–20；换个 seed 反而只差 6–12（与「同一段自己演几秒」的变化量约 21 同量级）。
      既不能复现、也压不住漂移，所以客户端**不自动生成种子**，只在调用方显式传时原样发过去
    - **参考图与首尾帧互斥（实测，别再试）**：想过「首帧锚画面 + 参考图锁角色」两手一起上，
      供应商明确不许 —— 两种写法都回
      `400 invalid_request：首尾帧素材与参考素材不能同时使用（param: mode）`
      （2026-09-23 实测；两次都在生成前被拒，**不消耗额度**）。
      `video_client.generate` 里的模式选择因此是有首帧就丢 `images`；
      想用参考图锁人物只能走 `reference` 模式（段与段之间变成硬切）。
      可用视频模型：`agnes-video-2.5-flash`（当前）/ `agnes-video-2.5` / `agnes-video-v2.0`
    - **实测：怎么压住「换脸」（2026-09-23 跑了三模式对照，产物在 `data/artifacts/_eval/`）**：
      拿一张正脸「定妆图」（图片模型生成）当锚，同样提示词各拍两段：
      ① keyframe 链（现在的做法）→ 构图/姿态真连续，但**死板**，而且**锚帧的毛病会被一路复制**
      （实测锚帧里的水印被原样录进画面、还从段1 末帧复制到了段2）；
      ② reference 模式每段都挂定妆图 → 人物最稳、画面干净、构图自由，代价是**段间硬切**；
      ③ reference + [定妆图, 上一段末帧] → 与 ② 看不出明显差别。
      三条路都**保住了同一张脸**，前提是有正脸定妆图 —— 反过来，锚帧是背影/远景时
      下一段拿不到人脸信息，只能自己编（这正是用户遇到的「后面几段换脸」）。
      结论：要「认脸」用 reference 模式 + 定妆图，要「一镜到底」用 keyframe 链，
      并且**每段收尾尽量留一个看得清人物的镜头**
    - **长视频默认「锚定人物与场景」**（`continuity=character`）：第 1 段照常出片，客户端
      **自动从它身上采 3 帧**（12% / 50% / 88% 处，`video_frames.sample_frames`）当「人物 / 场景
      基准」，之后**每一段都用 `reference` 模式挂上这几帧** —— 人脸与场景前后一致，段间是硬切。
      实测（`data/artifacts/_eval/锚定-*.jpg`）：两段 8 秒的走廊戏，残破墙皮 / 门洞 / 蓝绿光
      与人物（白 T 恤 + 黑背包）几乎一模一样。想要「一镜到底」的画质连续就传
      `continuity=seamless`（首尾帧链，人物靠单帧锚、容易飘）；有现成定妆图就传 `anchor`
      （本地图片文件名 → 那张；视频 → 采样几帧；**可以一次给多张**，逗号分开、最多 5 张 ——
      人物正脸 / 场景 / 服装各来一张比只给一张更稳），它优先当基准。
      采不到帧时会自动退回首尾帧链
    - **分段是边出边挂到聊天里的**：每段一出片就先挂一张卡片（`set_artifact_hook`），
      不用等整轮结束 —— 既让人看到进展，也能**发现内容不对就按 Esc 停**，
      不必等整个长视频白跑一遍；合成的长视频最后才追加。中途停掉或某段接不上时，
      已经出的段照样保留、照样给出去
    - 长视频进度写「第 2/3 段 · 视频生成中 47%…」：**段号在文案里、百分比是整体进度**
      （跨段单调递增，不会每段从 0 重来），并且 Esc 能真的中断（工具有 `set_cancel`）
    - **素材翻译由客户端负责，模型只给文件名**（这是模型最容易走偏的地方）：
      `first_frame` / `last_frame` 给**本地图片文件名**会读出内联成 `data:` 地址；给
      **某段视频的文件名**则取它末帧；`http(s)` 与 `data:` 原样透传。认不出来会当场报错
      并提示去看 `list_artifacts` —— **绝不把本地路径原样发出去**（供应商会回
      400「素材必须是公网 http(s) URL 或 Base64，不支持本地文件路径」）。
      工具描述里明确写了「**不要把 Base64 贴进来**」：一帧 720P 有十几万字符，
      模型的参数根本装不下，也没必要
    - **已有几段想接起来 → `merge_videos` 工具**（`videos=[文件名…]`，按顺序）：
      不重新生成、不消耗影片额度，`-c copy` 无损拼；参数不一致会自动先统一编码。
      有它是为了不让模型自己去 `execute_python` 调 ffmpeg —— 模型跑不了命令，
      也不该管这些
    - 视频接口只认图片地址，本地附件是内联成 `data:` 链接传的；若供应商不接受会退回文生视频并说明
- **多 API Key 请求池**：同一个模型可以填多个 API Key（每行一个），请求在它们之间轮换，
  降低触发限流（429）的概率
    - 某个 Key 命中 429 会自动换池里下一个 Key 重试，并把该 Key 冷却 60 秒
    - 冷却状态按「Base URL + 模型」跨请求保留，下一轮会直接跳过仍在冷却的 Key
    - Key 在界面上只显示打码结果，点「显示」才能查看 / 编辑
    - 全部 Key 都被限流时给出明确提示，而不是丢掉原始错误
- **消息区**：
    - 用户消息：浅色圆角气泡（右对齐）
    - 助手消息：全宽 Markdown（标题 / 列表 / 任务 / 表格 / 引用 / 代码块 / 链接）
    - 代码块基础高亮（Python / JS / C++ / SQL / Bash / JSON 等） + 一键复制
    - 悬浮操作：复制 / 重新生成 / 删除 / 字数统计
- **右侧结构面板**：
    - 从**真实文件**解析章节树（docx 优先读 Word 样式，pdf 按标题特征识别），
      自动跳过 Word 目录页、去掉文档标题，统计每节字数并推断「已完成 / 待写 / 进行中」
    - 一个对话里有多篇论文时可下拉切换，只展示所选那一篇；选择会被记住
    - 生成过程中实时跟随正在写的论文（优先按文件，尚未落盘时按正文）
    - 章节可逐级折叠 / 展开（默认折叠，标题左侧 `▶/▼`），支持一键展开或折叠全部
- **聊天内文档预览**：产物卡片上的「眼睛」按钮可在对话里**直接展开查看内容**，
  不必先下载再用 Office 打开
    - Word 按章节层级渲染（保留标题、正文、表格），PDF 按页、PPT 按页、Excel/CSV 转表格
    - 图片直接内联显示；文本 / Markdown 原样预览
    - 模型**正在写**同一份文档时预览会自动跟上（按修改时间 + 大小判断，收起后停止刷新）
    - 内容过长只预览开头并标注，不支持的类型给出提示
- **论文空间**：侧栏入口，按来源（我上传 / 模型生成）与时间列出本对话全部文件，
  可预览、打开、另存为、删除（只删应用数据目录内的文件，外部文件仅解除引用）
- **AIGC 检测**：侧栏底部第二个图标或设置菜单里的「AIGC 检测…」，上传 Word / PDF /
  文本后逐句判定并给出全文 AIGC 率
    - 判定分三档：**AI 生成（标红） / 疑似 AI（标黄） / 人工撰写（标灰）**，
      每句都列出命中理由（可预测性、搭配复用、模板化表达、句长规整度、突发性）
    - **章节标题与目录行不检测**；**参考文献整段不检测**；正文里的引文角标（`[1]`）
      统计时剔除；**过短的句子（少于 18 字）不会判成 AI**，按人工处理且不计入 AIGC 率
    - 灵敏度三档（宽松 / 标准 / 严格）只改判定阈值；检测在后台线程跑，长文不卡界面
    - 结果可**导出 PDF 报告**：**第 1 页**是结论（AIGC 率、风险等级、三档句数与
      字数占比、图例、排除说明），**第 2 页起是按原文排版着色后的全文标注稿** ——
      段落结构、句序、标题都跟源文档一致，只把每句话换成对应颜色（未判定的短碎片
      和参考文献用中性灰），打开就能直接对着原稿改，不用再一段段找
    - 支持把文档直接拖到窗口里；导出后自动用系统默认程序打开
    - **检测记录**：每次检测自动存一条（文件名 / 时间 / AIGC 率 / 风险等级 / 三档句数），
      对话框底部「检测记录」按钮或设置菜单可打开；左侧列表选一条即可回看当时的逐句
      标注、重新导出 PDF、删除或清空。记录最多保留最近 50 条
    - 算法见「AIGC 检测算法」一节，**为本地启发式估算，非官方检测口径**
- **文档产出（Word）**：
    - 论文排版：宋体正文小四、黑体分级标题、1.5 倍行距、首行缩进 2 字符
    - 三线表（含跨页重复表头）、图表题注、可更新的 Word 目录域、页脚页码
    - 正文里用 `![图 3-1 说明](配图文件名)` 可把已生成的配图真正嵌入 Word
    - 普通文档不会被套上论文规范
- **文档产出（PPT）**：16:9 演示文稿，自带版式而非纯白页
    - 封面页（主题色渐变底 + 装饰）、目录页（章节 ≥5 时自动生成）、内容页（标题色块 + 分隔线 + 页脚页码）
    - 要点分级（`##` 小节标题、`-` 一级、缩进两格降级）、Markdown 表格排成配色表格、图片插到页面右侧
    - 一页要点超过 6 条自动拆成续页
    - **背景图**：本地有素材就用本地的；没有时按讲题**自动联网生成**（横版、无水印，
      按「覆盖」方式铺满每页并叠半透明蒙版，保证压在上面的文字可读）
        - 同一主题只生成一次，之后命中缓存直接复用
        - 没有配置文生图 Key、或接口失败时自动回退主题色底，PPT 仍正常生成
    - 中文字体写进 `a:ea`，不会回退成默认宋体
- **会话工作区**：每次请求自动把本对话已有文件清单（名称 / 路径 / 来源 / 时间）
  注入给模型，模型不必再扫描磁盘找自己生成的文件
- **产物按会话分目录**（`services/session_artifacts.py`）：配图 / 视频 / Word / PPT / 下载
  都落在 ``data/artifacts/<会话 id>/``，和编程模式的 ``workspace/<会话 id>/`` 一个思路。
  以前全部平铺在 `data/artifacts/`（实测 200+ 个文件、58 个 mp4），而「按名字取文件」
  会扫整个目录兜底 —— 各会话的命名规则又一样（`视频-20260923-144501.mp4`），于是模型
  可能拿到**别的会话**刚生成的那份，用户看到的就是「**串文件**」。
  现在解析只认「本会话清单 → 本会话目录 → 根目录里的旧文件」，**绝不进别的会话目录**；
  升级前已生成的产物仍留在根目录（会话记录里存的是绝对路径，照旧能打开、能解析）。
  拿不到会话上下文时（脚本 / 测试 / 示例引擎）退回旧的平铺行为
- **流式输出**：分块渲染，60ms 节流
- **会话持久化**：每会话一个 JSON 文件，存放在数据目录 `sessions\` 下
- **文件管理**：
    - 同一对话里重复生成同名文档会**原地更新**，不再堆 `-1/-2` 副本
    - 删除对话时自动清理只属于它的产物 / 附件（其它对话仍引用的保留），
      并收掉它的空产物目录（`artifacts/<会话 id>/` 里还有文件就留着）
    - 设置菜单提供「清理未引用的文件」，回收历史遗留的产物 / 附件（顺带收掉空目录）
- **账号登录**：启动先弹出登录框，QQ 邮箱 + 4 位验证码注册，或邮箱 + 密码登录
    - 未登录时可用「离线使用」直接进入，本地功能不受影响
    - 服务地址默认 `http://127.0.0.1:8000`，登录框底部可改；登录态记在 `settings.ini`
- **账号中心**：侧栏左下角显示头像 + 昵称，点击打开「账号资料」
    - 内置 8 款头像（低饱和底色 + 线性图标），也可上传本地图片，自动裁成正方形保存
    - 昵称可修改，保存后同步到服务端（`PATCH /api/auth/profile`）
    - 新会话欢迎页顶部显示「欢迎回来，昵称」，未登录时隐藏
    - 退出登录 / 重新登录都在资料窗口完成
- **多会话并发**：每个会话各自一个生成任务，互不干扰 —— A 会话在出视频（动辄十几分钟）时，
  B 会话照样能提问；切会话不打断，流式输出各归各的消息（事件按消息 ID 路由，
  不在当前会话的内容直接写回它自己的模型，切回来就是完整的）。两道闸门：
  **同一个会话同时只跑一个**（同会话并发只会让上下文打架），**总数不超过
  `chat/maxParallel`**（默认 2；免费档的视频 / 生图很容易被限流，一起猛跑只会一起卡），
  到上限时提示「已经同时有 N 个任务在跑（上限 M 个）」。停止只停**当前会话**那一轮，
  别的会话不受牵连（`AgentService.stop(message_id)`）。并发上限可在
  `settings.ini` 的 `chat/maxParallel` 调整（1–8）
- **配置持久化**：数据目录 `settings.ini`（主题、模型、窗口几何、并发上限等）

## AIGC 检测算法

检测走的是与主流学术 AIGC 检测系统同构的「统计特征初筛 + 多维加权精判」路线，
但**完全离线**（不联网、不调用大模型），实现在 `paper_agent/services/aigc/`：

1. **抽取与切分**：Word 按段落 + 表格、PDF 按页抽文本，再按中英标点分句
   （小数点、缩写做了保护）。切分前先做三件事：
    - **跳过章节标题与目录**：`6.5.2 性能测试结果　31`、`第三章 车牌检测数据集构建`、
      `一、研究背景`、`Chapter 3` 这类标题行整行不参与统计（标题既不是作者写的句子，
      也没有上下文，混进去只会让句长规整度、搭配复用这些维度失真）；带引导点 /
      制表符 + 页码的目录行单独识别。正文里的编号列表（"1. 实验步骤如下…"、
      "3.2 节介绍了…"、日期 "2020.3.5…"）不会被误伤
    - **排除参考文献**：命中「参考文献 / References / Bibliography」标题后，其下
      文献表整体跳过（遇到「致谢 / 附录」这类标题再恢复）；没有标题、直接罗列
      条目的文档则按「编号开头 + 含 [J]/年份/出版社等文献特征」逐条识别
    - **剔除引文角标**：`[1]`、`[2-5]` 这类角标在同一篇里高频重复，会同时推高
      「搭配复用率」与「可预测性」，让引用密集的段落平白被判成 AI；它们不是
      作者写的词，统计时一并去掉
    - 过短碎片（标题、图注、编号，少于 10 字且 token 少于 5）连句子都不算
2. **语言模型**：用**文档自身**的字符 / 单词 bigram 模型估计每句平均信息量
   （bits/token）。平滑用一元回退，并且**扣掉本次出现自己**（留一法）——
   小语料上大量二元组只出现一次，不扣的话模型等于把句子背下来，信息量会全线塌掉。
3. **逐句打分**，五个维度加权：
   | 维度 | 含义 | 权重 |
   |---|---|---|
   | 可预测性 | 句子信息量在全文中的相对位置（越低越像 AI） | 0.30 |
   | 模板化密度 | "首先 / 综上所述 / 本研究 / 实验结果表明…" 的命中密度 | 0.22 |
   | 搭配复用率 | 句子里的二元组有多少在全文别处也出现过 | 0.18 |
   | 篇幅规整度 | 句长是否落在 AI 常见的舒适区 | 0.15 |
   | 突发性 | 句长相对全文的偏离（人类长短句交错） | 0.15 |

   **短句先合并，再判定**（`merge_short_sentences`）：少于 18 字的句子会顺着
   往后并，凑够长度后作为一个整体打分。短句之所以要特殊处理，是因为它 token
   太少、统计特征不可靠；但「不可靠」不等于「安全」—— AI 完全可以通篇用短句
   写作（"该方法效果显著。实验数据充分。结果表明有效。"），只放过短句就会整段
   漏检。

   合并到没有邻居可并时（比如整篇就一句"本系统采用 B/S 架构。"），才按**人工**
   标注、**不计入 AIGC 率**，但仍会出现在标注列表与 PDF 里，理由里注明
   「片段过短，统计特征不可靠」。段落末尾凑不满的残留并入上一组，不会丢字。

   段落层面还有一次同样的合并（`_merge_short_paragraphs`）：一行一句的排版很常见
   （AI 的列表体喜欢这么写，PDF / Word 抽取也更容易把正文切成这样），这时**每个
   段落只有一个短句，段内没有邻居可并**，只合并句子就会留下满屏「片段过短」。
   所以连续短段落也会攒够判定长度后自成一组；攒不满的残段并进上一段。换行符
   保留在文本里，导出的原文标注仍然按原样断行。
4. **文档级校准**：把全文 token 打乱（固定种子）重算一遍信息量当作「无结构」基线，
   得到**语言冗余度** `1 - H₂ / H_shuffled`；再叠加句长变异系数，对整篇统一上调 /
   下调。打乱基线抵消了语料规模的影响，长文不会因为重复机会多就被一律判成 AI。
5. **聚合**：先按阈值把每句分成三档（标准档 0.62 / 0.45），再按档位折算：

   **AIGC 率 =（AI 生成句字数 × 1.0 + 疑似 AI 句字数 × 0.5）÷ 参与统计的总字数**

   按档位折算（而不是直接对倾向分取平均）是为了让 AIGC 率与界面上的三档计数
   **严格一致** —— 「AI 0 句 / 疑似 0 句」就一定是 0%。红色加黄色的部分，
   就是 AIGC 率。各句倾向分的加权平均另存为 `average_score`，在界面与报告里以
   「平均每句倾向」给出，用于交叉参考。

   > 早期版本直接拿倾向分的加权平均当 AIGC 率，会出现「三档都是 0，AIGC 率却
   > 有 30%」的矛盾：一批句子的分数卡在疑似阈值下方时，没有一句越线，平均值
   > 却不低；而「可预测性」「突发性」用的是相对全文的位置，句子处于平均位置就
   > 记 0.5，把纯人工文稿的基线也抬到了 20~30%。现口径已按档位折算修正。
6. **留档原文结构**：分句时同时记录每句在段落里的偏移（`split_sentence_spans`），
   段落流（含被排除的标题 / 文献行）一并保存在 `AigcReport.layout`，导出时才能
   把段落按原样拼回去、只换颜色。

风险分级：<20% 低风险、<40% 需关注、<60% 风险较高、≥60% 高风险。

**局限**：这是启发式估算，与知网 / 格子达等官方系统的语料、模型、阈值都不同；
语言高度规范的原创学术写作可能被误判，深度人工改写过的 AI 文本也可能漏检。
结果仅供参考，不能作为学术判定依据。

## 数据目录

运行时数据（会话、附件、智能体生成的文件产物、配置）统一放在一个数据目录，取值优先级：

1. 环境变量 `PAPERAGENT_DATA_DIR`
2. 源码启动时：项目根 `data\`（数据跟着项目走，不占用系统盘）
3. 以上都没有：系统用户目录 `%APPDATA%\PaperAgent`（其它平台对应 `~/.local/share/PaperAgent`）

首次启动时若发现旧系统盘目录里已有历史数据，会自动搬到新的数据目录，并把会话 JSON 里
记录的绝对路径一并改写为新的位置。

子目录用途：`sessions/` 会话、`attachments/` 你上传的文件、`artifacts/` 模型产出的文件、
`avatars/` 头像、`aigc/` AIGC 检测记录（一次检测一个 JSON，含逐句标注与原文段落流）、
`cache/` 背景素材缓存，配置在 `settings.ini`。

## 账号服务

注册登录由配套服务端 **Paper_Agent_Server**（FastAPI）提供，它开两个端口：

| 服务 | 地址 | 说明 |
| --- | --- | --- |
| API | `http://127.0.0.1:8000` | 邮箱验证码 / 注册 / 登录 / 资料 |
| 用户看板 | `http://127.0.0.1:8010` | 浏览器查看注册用户（昵称 / 邮箱 / 账号密码） |

```powershell
cd ..\Paper_Agent_Server
pip install -r requirements.txt
python run.py          # 同时启动 8000 与 8010
```

服务端没启动时桌面端也能用「离线使用」进入，只是没有登录态（也没有内置模型的代理密钥）。

### 大模型代理

桌面端的内置模型不直连供应商，Base URL 指向服务端：

```
对话：桌面端 ──(Bearer 用户密钥)──▶ 服务端 /api/llm/v1/chat/completions ──(供应商 Key)──▶ 大模型
出图：桌面端 ──(Bearer 用户密钥)──▶ 服务端 /api/llm/v1/images/generations ──(供应商 Key)──▶ 供应商
```

- 服务端看板「大模型与密钥」页签里维护模型地址、**显示名与备注**（会下发到桌面端的
  模型下拉框）与**供应商密钥池**（可多把轮换、命中限流自动冷却换下一把）；
  **新增内置模型也在看板里做**，配好密钥后桌面端登录取一次就能选
- 每个用户在服务端有一把（或多把）**代理密钥**，可设有效期 / 续期 / 停用 / 删除；
  密钥不对或已过期的请求由服务端直接拒绝
- 桌面端登录后自动调 `/api/llm/user-key` 取回密钥并存在 `settings.ini` 的
  `llm/userKey`，退出登录时清掉；流式输出经服务端原样透传
- 桌面端访问服务端的请求都带 `PaperAgent-Desktop/<版本>` 的 User-Agent
  （`core/constants.SERVER_USER_AGENT`）：服务端的**请求日志**靠它把正常桌面流量
  和脚本刷接口区分开，排查异常来源时不会把自家客户端当成攻击者

服务端的具体配置见 `Paper_Agent_Server/README.md` 的「大模型代理」与「请求日志」两节。
